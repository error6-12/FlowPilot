# Multi-Agent 平台架构与协作机制

## 一、平台概述

本平台采用 Multi-Agent 架构，由多个专职 Agent 协同处理企业员工的各类需求。每个 Agent 有明确的职责边界，通过中央协调器进行任务分配和信息共享。

## 二、Agent 角色与分工

### 2.1 Agent 角色清单
| Agent 名称 | 职责 | 触发场景 |
|-----------|------|---------|
| **意图分类 Agent** | 识别用户意图，路由到对应 Agent | 所有用户输入 |
| **知识问答 Agent** | 基于 RAG 检索知识库回答员工问题 | "出差标准是多少？""年假怎么算？" |
| **流程发起 Agent** | 引导员工发起各类流程，提取/补全字段 | "帮我请假""提交一个报销单" |
| **流程查询 Agent** | 查询流程状态、进度、历史记录 | "我的请假到哪了？""查一下IT工单状态" |
| **审批提醒 Agent** | 提醒审批人处理待办、超时催办 | 有待审批流程、审批即将超时 |
| **材料预审 Agent** | 检查提交材料是否完整合规 | 流程提交前自动触发 |
| **流程校验 Agent** | 校验流程逻辑（金额标准、审批链路、权限） | 流程提交时自动触发 |
| **协作协调 Agent** | 处理跨流程联动、多流程并行场景 | 同时涉及多个流程时触发 |

### 2.2 各 Agent 详细说明

#### 意图分类 Agent
- **输入**：用户原始消息
- **输出**：意图标签 + 置信度 + 路由目标
- **路由规则**：
  - 知识问答类 → 知识问答 Agent
  - 流程发起类 → 流程发起 Agent
  - 流程查询类 → 流程查询 Agent
  - 审批操作类 → 审批提醒 Agent
  - 多意图/复杂场景 → 协作协调 Agent

#### 材料预审 Agent
- **触发时机**：流程提交前
- **检查内容**：
  - 必填字段是否完整
  - 附件是否上传
  - 金额是否合理（超标提醒）
  - 时间是否合规（如请假是否提前足够天数）
- **输出**：预审结果（通过/需补充/不合规）

#### 流程校验 Agent
- **触发时机**：材料预审通过后
- **检查内容**：
  - 审批链路是否正确
  - 预算余额是否充足
  - 是否有重复提交
  - 权限是否满足
- **输出**：校验结果 + 修正建议

#### 协作协调 Agent
- **触发时机**：用户同时涉及多个流程
- **职责**：
  - 识别流程间依赖关系
  - 协调多 Agent 共享表单信息
  - 处理流程间的冲突
  - 编排多流程执行顺序

## 三、Agent 间信息共享机制

### 3.1 共享数据结构
所有 Agent 共享一个统一的**会话上下文（Session Context）**：
```json
{
  "session_id": "唯一会话ID",
  "user_id": "用户ID",
  "user_name": "用户姓名",
  "user_role": "用户角色",
  "department": "所属部门",
  "intent": "识别的意图",
  "extracted_fields": {
    // 各Agent提取的字段统一存储
  },
  "active_flows": [
    // 当前正在处理的流程
  ],
  "shared_memory": {
    // Agent间共享的中间结果
  }
}
```

### 3.2 避免重复填写
当用户同时发起多个流程时（如"合同评审 + 预算申请"）：
1. **协作协调 Agent** 接管，识别两个流程的共有字段
2. **共有字段**（如项目名称、申请人、部门）只需用户提供一次
3. 各流程的**专有字段**分别引导用户填写
4. 提交时，共享字段自动填充到两个流程中

### 3.3 信息共享示例
```
用户："帮我同时提交合同评审和预算申请，都是关于XX项目的"

Agent执行流程：
1. 意图分类 → 识别为"多流程发起" → 路由到协作协调Agent
2. 协作协调Agent → 提取共有字段：项目名称=XX项目
3. 流程发起Agent → 引导填写合同评审专有字段（合同方、金额、期限）
4. 流程发起Agent → 引导填写预算申请专有字段（预算科目、金额明细）
5. 材料预审Agent → 分别检查两个流程的材料完整性
6. 流程校验Agent → 分别校验两个流程的合规性
7. 确认展示 → 用户一次性确认两个流程
8. 提交 → 两个流程同时提交，自动关联
```

## 四、Agent 通知机制

### 4.1 材料缺失通知
当材料预审 Agent 发现材料缺失时：

| 通知方式 | 适用场景 | 通知内容 |
|---------|---------|---------|
| Agent对话回复 | 用户在对话中 | "您的报销申请缺少XX材料，请补充" |
| 企业微信消息 | 用户不在对话中 | 推送卡片消息，含补充入口 |
| 邮件通知 | 紧急/重要事项 | 邮件通知 + 操作链接 |

### 4.2 补充后重新核验
- 用户补充材料后，**材料预审 Agent** 自动重新核验
- 核验通过 → 自动进入下一步（流程校验）
- 核验不通过 → 再次通知用户，说明仍缺失的内容
- 最多自动核验3次，超过3次转人工处理

## 五、Agent 处理记录归档

### 5.1 记录内容
每次 Agent 处理都会生成一条执行记录：
```json
{
  "record_id": "记录ID",
  "session_id": "会话ID",
  "timestamp": "执行时间",
  "user_id": "用户ID",
  "agent_chain": ["意图分类Agent", "材料预审Agent", "流程发起Agent"],
  "actions": [
    {
      "agent": "Agent名称",
      "action": "执行的操作",
      "input_summary": "输入摘要",
      "output_summary": "输出摘要",
      "duration_ms": 123
    }
  ],
  "knowledge_retrieved": ["检索到的知识库文档列表"],
  "tools_called": ["调用的工具列表"],
  "result": "最终结果",
  "status": "success/fail"
}
```

### 5.2 归档位置
- **执行日志**：保存在平台管理后台，保留1年
- **对话记录**：保存在用户会话历史中，保留3年
- **知识库检索记录**：保存在RAG系统中，保留1年

### 5.3 查询方式
- **用户**：可在"我的Agent对话"中查看历史对话记录
- **Agent运营**：在管理后台查看全量执行日志，支持按用户、时间、Agent、状态筛选
- **管理员**：可查看完整日志（含脱敏后的敏感信息）

## 六、Agent 冲突处理机制

### 6.1 冲突场景
- **材料预审Agent** 说"材料齐全"，但**流程校验Agent** 说"缺少必要附件"
- **知识问答Agent** 给出的答案与**流程发起Agent** 的校验规则矛盾
- 两个 Agent 对同一字段给出不同的校验结论

### 6.2 冲突解决策略
| 优先级 | 策略 | 说明 |
|--------|------|------|
| 1 | **协作协调Agent仲裁** | 协调Agent综合两方意见，按业务规则做出判断 |
| 2 | **保守原则** | 冲突时优先采用更严格的结论（如"需要补充材料"优先于"材料齐全"） |
| 3 | **转人工** | 无法自动仲裁时，标记为"需人工确认"，转交对应业务部门处理 |

### 6.3 转人工介入
| 冲突类型 | 转给谁 |
|---------|--------|
| 报销标准理解不一致 | 财务部 |
| 请假制度理解不一致 | HR |
| 审批链路争议 | HR + IT |
| 系统规则与制度矛盾 | Agent运营 + 业务部门 |

### 6.4 冲突记录
- 所有冲突都会记录在案，包括冲突原因、解决方式和最终结论
- 运营团队定期分析冲突记录，优化Agent规则和Prompt
- 高频冲突场景会被标记，优先修复

## 七、常见问题FAQ

### Q1: Agent处理我的请求时，能看到我的个人信息吗？
**A**: Agent会根据数据权限规则访问必要信息。敏感字段（如银行卡号）在处理过程中会脱敏。详见 `data_access_control.md`。

### Q2: 同时提两个流程，会不会一个成功一个失败？
**A**: 会。每个流程独立校验和提交。如果一个失败，另一个不受影响。失败的流程会提示具体原因，可修改后重新提交。

### Q3: Agent给的回答和制度不一致怎么办？
**A**: Agent的回答基于知识库检索，可能存在理解偏差。建议以制度原文为准，并可向Agent运营团队反馈，帮助优化。

### Q4: 我能要求换一个Agent处理吗？
**A**: Agent路由由系统自动判断，不支持手动选择。如对Agent处理结果不满意，可选择"转人工"。
