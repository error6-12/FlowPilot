## 晋升条件

### 1. 基本条件
| 条件 | 要求 |
|------|------|
| 在职时长 | 当前职级满1年（T1→T2满6个月即可） |
| 绩效要求 | 最近4个季度绩效均B+及以上，且至少1个A |
| 价值观 | 无价值观违规记录 |
| 培训学分 | 完成年度培训学分要求 |
| 360评估 | 360度评估达标（上级/同事/下级/跨部门） |

### 2. 晋升评审标准

#### T1 → T2（初级→中级工程师）
- 能独立完成分配的模块开发任务
- 掌握岗位所需基本技能
- 代码质量达标，bug率低于团队平均
- 有至少1个完整项目经验

#### T2 → T3（中级→高级工程师）
- 能独立负责完整项目或核心模块
- 具备一定的系统设计能力
- 能指导初级工程师
- 至少主导1个中等复杂度项目
- 在技术分享中有至少1次团队分享

#### T3 → T4（高级→资深工程师）
- 能主导复杂系统/平台的设计与开发
- 深入掌握至少1个技术领域
- 能跨团队协作推动技术方案落地
- 有显著的技术贡献（性能优化、架构升级等）
- 带教1-2名初/中级工程师

#### T4 → T5（资深→技术专家）
- 在某一技术领域有深入研究和突出贡献
- 能主导公司级技术架构设计
- 能引领技术方向，推动技术选型决策
- 有行业影响力（技术博客、开源贡献、专利等加分）
- 培养多名技术骨干

### 3. M序列晋升补充要求
- **M1→M2**：团队绩效达标，具备跨团队协调能力
- **M2→M3**：能管理多个团队，有战略分解和落地能力
- **M3→M4**：能制定部门级战略，推动组织变革
- **M4→M5**：能影响公司级战略决策

## 晋升流程

### 1. 晋升周期
- **定期晋升**：每年两次（4月、10月）
- **破格晋升**：随时可申请，需VP及以上推荐

### 2. 晋升流程
```
1. 员工自荐/主管推荐
   ↓
2. 提交晋升申请材料
   ↓
3. 资格审查（HR）
   ↓
4. 晋升评审会
   ↓
5. 评审结果公示（5个工作日）
   ↓
6. 正式任命
```

### 3. 晋升申请材料
- 个人述职报告
- 工作成果总结（项目、数据、贡献）
- 技术/业务论文或总结（T3及以上）
- 同事/合作伙伴评价
- 直属领导推荐意见

### 4. 晋升评审会
- **评审委员会**：跨部门评委组成
- **评审形式**：述职答辩（15分钟陈述 + 15分钟问答）
- **评审维度**：
  - 专业能力（40%）
  - 业务贡献（30%）
  - 影响力/带教（20%）
  - 价值观（10%）

## 薪酬调整

### 晋升调薪
| 晋升类型 | 调薪幅度 |
|---------|---------|
| 正常晋升（同序列升级） | 10%-20% |
| 跨序列晋升 | 15%-25% |
| 破格晋升 | 20%-30% |

### 年度调薪
- **时间**：每年4月
- **依据**：年度绩效、市场薪酬水平、公司经营状况
- **调整范围**：
  - 绩效A：15%-30%
  - 绩效B+：8%-15%
  - 绩效B：3%-8%
  - 绩效C：不调整

## 破格晋升

### 适用情形
- 在公司级关键项目中做出突出贡献
- 解决重大技术难题，产生显著业务价值
- 获得行业/国家级重要奖项
- 为公司带来重大商业价值

### 申请方式
- 需VP级及以上领导推荐
- 提交突出贡献说明
- CEO或CTO审批

## 降级机制

### 降级条件
- 连续2个季度绩效为C
- 严重违反价值观
- 重大工作失误造成损失
- 管理能力不胜任（管理岗）

### 降级影响
- 职级下调1级
- 薪酬相应调整
- 降级后满1年可重新申请晋升

## 常见问题FAQ

### Q1: 晋升需要考证书吗？
**A**: 不强制要求，但相关证书（如PMP、AWS认证、CFA等）在评审中会作为加分项。

### Q2: 转序列晋升需要降级吗？
**A**: 不需要降级。转序列按能力匹配目标职级，薪酬就高不就低。

### Q3: 晋升失败后多久可以再申请？
**A**: 至少等待下一个晋升周期（6个月）。建议根据评审反馈针对性提升。

### Q4: 可以不晋升只做技术吗？
**A**: 可以。技术序列和管理序列并行，不强制转管理。T序列同样有高薪和发展空间。

### Q5: 新入职员工什么时候可以晋升？
**A**: 正常入职满1年可申请晋升；如果入职前已有丰富经验，入职定级时可直接定到较高级别。
