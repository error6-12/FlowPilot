# Agent运营管理指南

## 一、概述

本指南面向Agent运营人员，帮助管理Multi-Agent系统的日常运营、监控、优化和迭代。

## 二、Agent执行监控

### 2.1 执行日志查看

#### 日志内容
每次Agent执行都会记录以下信息：
```
{
  "session_id": "会话唯一标识",
  "user_id": "用户ID",
  "timestamp": "执行时间",
  "intent": "识别的用户意图",
  "routed_to": "路由到的Agent名称",
  "tools_called": ["调用的工具列表"],
  "knowledge_retrieved": ["检索到的知识库文档"],
  "response": "最终回复内容",
  "latency_ms": 1234,
  "token_usage": {
    "prompt_tokens": 500,
    "completion_tokens": 200
  },
  "status": "success/fail"
}
```

#### 查看方式
1. **管理后台**：`admin.company.com/agent/logs`
2. **命令行**：通过运维脚本查询日志
3. **Agent对话**：管理员可问"查看最近的错误日志"

### 2.2 监控指标

| 指标 | 说明 | 健康阈值 |
|------|------|---------|
| 响应延迟 | 从收到请求到返回结果的耗时 | P95 < 5秒 |
| 意图识别准确率 | 路由分类的正确率 | ≥ 95% |
| 工具调用成功率 | 工具调用的成功比例 | ≥ 99% |
| 知识检索命中率 | RAG检索到相关文档的比例 | ≥ 90% |
| 用户满意度 | 用户对回答的评分 | ≥ 4.0/5.0 |
| Token消耗 | 每次请求的平均Token使用量 | 根据预算设定 |

### 2.3 告警规则
| 告警级别 | 触发条件 | 通知方式 |
|---------|---------|---------|
| P0-紧急 | 服务不可用、错误率>10% | 电话+短信+企业微信 |
| P1-严重 | 响应延迟P95>10秒、工具调用失败率>5% | 短信+企业微信 |
| P2-警告 | 响应延迟P95>8秒、检索命中率<80% | 企业微信 |
| P3-提示 | 日活异常波动、Token消耗超标 | 邮件 |

## 三、错误分析与排查

### 3.1 常见错误类型

#### 路由错误
| 错误现象 | 可能原因 | 排查方法 |
|---------|---------|---------|
| 错误路由到不相关Agent | 意图分类Prompt不准确 | 查看分类日志，调整Prompt |
| 无法识别用户意图 | 缺少相关意图定义 | 补充意图分类规则 |
| 多轮对话上下文丢失 | 会话管理异常 | 检查session管理逻辑 |

#### 工具调用错误
| 错误现象 | 可能原因 | 排查方法 |
|---------|---------|---------|
| 工具调用失败 | 工具参数格式错误 | 检查参数Schema定义 |
| 工具超时 | 下游服务响应慢 | 检查下游服务健康状态 |
| 工具返回异常 | 外部接口变更 | 核对接口文档和返回值 |

#### 知识检索错误
| 错误现象 | 可能原因 | 排查方法 |
|---------|---------|---------|
| 检索不到相关内容 | 知识库缺少相关知识 | 补充知识库文档 |
| 检索到不相关文档 | 文档切分不合理或Embedding质量问题 | 调整切分策略或更换Embedding模型 |
| 回答与检索内容不符 | 生成Prompt问题 | 优化RAG生成Prompt |

### 3.2 排查流程
```
1. 定位问题 → 查看日志确认错误发生时间和具体表现
   ↓
2. 复现问题 → 使用相同输入复现错误
   ↓
3. 分析原因 → 检查日志中的中间步骤（路由/工具/检索）
   ↓
4. 修复验证 → 修复后在测试环境验证
   ↓
5. 上线观察 → 灰度发布后监控指标
```

## 四、Prompt管理

### 4.1 Prompt版本管理
- 所有Prompt存储在配置中心，支持版本控制
- 每次修改需记录变更原因和预期效果
- 支持快速回滚到历史版本

### 4.2 Prompt优化流程
```
1. 发现效果不佳的case
   ↓
2. 收集同类badcase（至少10个）
   ↓
3. 分析badcase共性，定位Prompt问题
   ↓
4. 修改Prompt并在测试集上验证
   ↓
5. A/B测试对比效果
   ↓
6. 全量上线
```

### 4.3 Prompt最佳实践
- 明确定义Agent角色和职责边界
- 使用结构化输出（JSON Schema）
- 包含few-shot示例提高准确率
- 设置兜底策略（无法处理时的默认回复）
- 定期review和优化

## 五、Skill管理

### 5.1 Skill注册
每个工具/Skill需注册以下信息：
```
{
  "skill_name": "技能名称",
  "description": "功能描述",
  "input_schema": "输入参数定义",
  "output_schema": "输出参数定义",
  "timeout_ms": 5000,
  "retry_policy": {
    "max_retries": 3,
    "backoff_ms": 1000
  },
  "owner": "负责人",
  "version": "1.0.0"
}
```

### 5.2 Skill版本管理
- 每个Skill独立版本号（语义化版本）
- 向后兼容的改动：修订号+1
- 新增功能：次版本号+1
- 不兼容变更：主版本号+1
- 旧版本保留一段时间，支持平滑迁移

### 5.3 Skill监控
- 调用次数、成功率、平均耗时
- 错误分类统计
- 依赖服务健康状态

## 六、知识库管理

### 6.1 知识库更新流程
```
1. 发现知识缺失或过时
   ↓
2. 编写/更新文档
   ↓
3. 文档审核（确保准确性和完整性）
   ↓
4. 导入知识库（重新Embedding和索引）
   ↓
5. 检索测试（验证能检索到新内容）
   ↓
6. 上线
```

### 6.2 知识库质量指标
| 指标 | 说明 | 目标 |
|------|------|------|
| 覆盖率 | 用户问题能在知识库中找到答案的比例 | ≥ 90% |
| 准确率 | 检索到的文档与问题相关的比例 | ≥ 95% |
| 时效性 | 知识库文档的更新频率 | 关键政策变更后24小时内更新 |
| 完整性 | 文档内容是否覆盖所有场景 | 定期review |

### 6.3 知识库结构规范
- 按业务领域分目录管理
- 每个文件聚焦一个主题
- 包含关键词段便于检索
- FAQ段落采用问答格式
- 定期review和更新

## 七、评测体系

### 7.1 评测集建设

#### 评测集类型
| 类型 | 内容 | 数量要求 |
|------|------|---------|
| 意图识别评测集 | 各类用户问题及正确分类 | ≥ 500条 |
| 知识问答评测集 | 问题+标准答案+引用文档 | ≥ 300条 |
| 流程办理评测集 | 流程场景+期望的交互过程 | ≥ 100条 |
| 边界case集 | 无法处理或需要特殊处理的情况 | ≥ 50条 |

#### 评测集维护
- 每次发现新的badcase，加入评测集
- 每月review一次评测集覆盖面
- 新增业务场景时同步更新评测集

### 7.2 评测指标

| 评测维度 | 指标 | 计算方式 |
|---------|------|---------|
| 路由准确率 | 意图分类正确率 | 正确路由数/总数 |
| 回答准确率 | 答案正确率 | 正确回答数/总问题数 |
| 检索召回率 | 相关文档被检索到的比例 | 命中相关文档数/应命中总数 |
| 任务完成率 | 流程成功办理的比例 | 成功完成数/总请求数 |
| 回答完整性 | 答案是否包含所有必要信息 | 人工评估 |

### 7.3 A/B测试
- 修改Prompt/Skill/知识库后需做A/B测试
- 实验组与对照组各分配50%流量
- 测试周期至少7天
- 对比核心指标，确认提升后再全量

### 7.4 评测报告模板
```
评测日期：YYYY-MM-DD
评测版本：vX.X.X
评测集版本：vX.X.X

## 核心指标
- 路由准确率：XX.X%（对比上次 ±X.X%）
- 回答准确率：XX.X%（对比上次 ±X.X%）
- 检索召回率：XX.X%（对比上次 ±X.X%）
- 任务完成率：XX.X%（对比上次 ±X.X%）

## Badcase分析
| 序号 | 用户输入 | 期望结果 | 实际结果 | 原因分析 |
|------|---------|---------|---------|---------|

## 改进建议
1. ...
2. ...
```

## 常见问题FAQ

### Q1: 如何发现Agent回答不准确？
**A**: 主要通过三个渠道：用户反馈（点踩）、运营巡检（随机抽查对话日志）、评测集定期评测。

### Q2: 知识库更新后需要多久生效？
**A**: 文档更新后需要重新Embedding和索引，通常15-30分钟内生效。紧急更新可手动触发重建索引。

### Q3: Prompt修改后效果变差了怎么办？
**A**: 立即回滚到上一版本。然后分析badcase，在测试集上验证改进方案后再上线。所有Prompt变更都要有版本回退能力。

### Q4: 如何评估一次优化的效果？
**A**: 使用评测集进行A/B测试，对比核心指标（准确率、召回率、完成率）。至少运行7天，排除偶然波动。

### Q5: Token消耗过高怎么优化？
**A**: 1) 优化Prompt，减少冗余描述；2) 优化检索策略，减少不必要的context；3) 使用更小的模型处理简单任务；4) 设置Token预算告警。
